devctx Documentation

devctx is a local-first code context engine and MCP (Model Context Protocol) server written in Go. It indexes your repository's AST symbols, full-text content, and git state into an embedded SQLite database — giving AI coding agents sub-millisecond access to exact code context without reading entire files.

v1.0.0 Go 1.22+ Windows · macOS · Linux MIT License Zero cloud dependencies
Why devctx? Without a context engine, an AI agent reading a 1,200-line controller file costs ~6,500 tokens per turn. With devctx get_file_skeleton, the same file costs ~120 tokens — a 98% reduction. On large codebases this saves tens of dollars per coding session.

How It Works

devctx runs in two modes that complement each other:

CLI Mode

Direct terminal commands for developers: devctx search, devctx symbol, devctx blast. Results print to stdout in clean, readable format.

MCP Server Mode

Run devctx serve to start a JSON-RPC 2.0 server over stdio. AI coding agents (Claude, Antigravity, Cursor) call its 14 typed tools directly via the Model Context Protocol.

Index Layer

A multi-threaded scanner walks the repository, extracts AST symbols using per-language parsers, and writes everything to a single .devctx/index.db SQLite WAL file. Index time: ~1.2s for 1,500 files.

Auto Sync

devctx watch monitors the filesystem and incrementally re-indexes changed files in <100ms. Git hooks (post-commit, post-checkout) keep the index current automatically.

Installation

devctx ships as a single self-contained binary. No runtime, no dependencies.

macOS & Linux

bash 
curl -fsSL https://recscse.github.io/devctx/install.sh | bash

The script downloads the correct binary for your OS/arch, installs it to /usr/local/bin/devctx, and verifies the checksum.

Windows (PowerShell)

powershell 
irm https://recscse.github.io/devctx/install.ps1 | iex

Installs to %LOCALAPPDATA%\devctx\bin\devctx.exe and adds it to the user PATH.

Windows (CMD / curl)

cmd 
curl -fsSL https://recscse.github.io/devctx/install.cmd -o install.cmd && install.cmd && del install.cmd

Build from source

bash 
git clone https://github.com/recscse/devctx
cd devctx
go build -o devctx .
# Or use the Makefile:
make build          # local binary
make build-all      # cross-compile all platforms to dist/

Quickstart

  1. Install devctx

    Follow the installation instructions above for your OS.

  2. Configure AI agent integrations

    Run once to auto-detect and register devctx as an MCP server in all installed AI coding tools:

    bash
    devctx setup

  3. Index your repository

    Navigate to any repository and build the index. Takes 1–2 seconds for most codebases.

    bash
    cd /path/to/my-repo
devctx init

  4. Install git hooks (optional but recommended)

    Keeps the index synchronized automatically after every commit and branch switch:

    bash
    devctx install-hooks

  5. Done — open your AI coding tool

    Claude Code, Cursor, Antigravity, or VS Code will now call devctx's MCP tools automatically when working in this repository.

CLI: Index Management

devctx init [path]

Scan a repository and build the SQLite index from scratch. Uses a parallel goroutine pool (2× CPU cores) for concurrent file reading and AST extraction.

bash
devctx init                    # current directory
devctx init /path/to/repo      # explicit path
devctx init . --json           # JSON output for CI/scripting

Output: live progress bar with file count and throughput, then a summary table with indexed file count, symbol count, primary language, and total latency.

devctx update [path]

Incrementally re-index only files that have changed since the last index. Reads git status to identify modified files. Typical latency: <100ms.

devctx reindex [path]

Drop the existing index and rebuild from scratch. Use when the schema has changed after an upgrade, or when the index is corrupted.

devctx watch [path]

Start a background filesystem watcher that automatically calls update whenever source files are saved. Uses OS-native file events (inotify / FSEvents / ReadDirectoryChangesW).

devctx status [path]

Display the current index state: total files, size on disk, last sync timestamp, and a language breakdown table.

output
  devctx  Status

  Repository            /work/my-repo
  Indexed Files         176 files
  Total Size            711.74 KB
  Last Updated          Tue, 02 Sep 2026 12:58:43 +0530
  Primary Language      Java

  Language Breakdown
    Java          168 files   95.5%
    XML             6 files    3.4%
    Markdown        2 files    1.1%

CLI: Code Search

devctx search <query> [path]

Full-text search across all indexed files using SQLite FTS5. Returns file paths and snippet context. Typical latency: <2ms.

bash
devctx search "PaymentProcessor"
devctx search "@Scheduled"
devctx search "spring-boot-starter-web"   # searches pom.xml dependencies

CLI: Symbol Lookup

devctx symbol <name> [path]

Find class, function, method, interface, or annotation definitions matching a name pattern. Returns exact file path, line number, and full signature.

output
  devctx  Symbol Results

  1.  EventController                     [class]
       src/main/java/.../EventController.java:41
       @Slf4j @RestController @RequestMapping("/v1/event") public class EventController

  2.  @RestController                     [annotation]
       src/main/java/.../EventController.java:37

devctx refs <symbol> [path]

Find all call sites, import statements, and usages of a given symbol across the entire repository.

CLI: Blast Radius

devctx blast <symbol> [path]

Before modifying a function or class, calculate its blast radius: all upstream callers, affected files, and linked test suites. Prevents unexpected CI breakage.

bash
devctx blast GenerateToken
devctx blast PaymentProcessor --json

CLI: Git Diff

devctx diff [path]

Show uncommitted changes mapped to enclosing AST symbols. Unlike git diff, this shows which functions changed — not just which lines — making it far more useful as context for an AI agent.

CLI: Feature Pack

devctx pack <topic> [path]

Build a token-optimized context bundle for a feature area. Combines: relevant symbol definitions, file skeletons, related test suites, and stored architectural decisions — all in one compact output ready to paste into an LLM prompt.

CLI: Repo Map

devctx map [path]

Print a directory-organized, symbol-annotated structural map of the repository. Supports --web to launch an interactive D3 network graph in the browser.

bash
devctx map             # print to terminal
devctx map --web       # open interactive browser graph on :7890

CLI: Architectural Decisions

devctx decisions [topic]

View architectural decisions recorded by AI agents during previous sessions. Decisions are stored in the local SQLite index and persist across IDE restarts, so agents don't re-debate the same design choices.

CLI: Setup & Hooks

devctx setup [path]

Auto-detect all installed AI coding tools and register devctx as an MCP server. Supports: Google Antigravity, Claude Desktop, Claude Code, Cursor IDE, VS Code (Continue, Cline), Windsurf.

devctx install-hooks [path]

Install post-commit and post-checkout git hooks that call devctx update automatically. This keeps the index continuously synchronized without any developer effort.

devctx init-rules [path]

Auto-generate a .cursorrules / AGENTS.md / .windsurfrules file tailored to the detected language, framework, and project structure. Gives AI agents upfront architectural context.

CLI: MCP Server

devctx serve [path]

Start the Model Context Protocol server over stdio. This is called automatically by your AI coding tool based on the configuration written by devctx setup. You do not normally run this manually.

bash
# Only if configuring manually:
devctx serve /path/to/repo
Workspace Auto-Detection: The MCP server automatically resolves the correct index for the workspace an AI agent is working in. If no index is found, it triggers a background auto-index. You never need to pass explicit paths from within an AI coding session.

MCP Tools Reference

When running as an MCP server, devctx exposes 14 deterministic tools. All tools accept an optional workspace_path string argument to target a specific repository if multiple are indexed.

get_repo_map

Returns a directory-organized map of all indexed files annotated with symbol signatures. Use this as the very first tool call to orient an agent in an unfamiliar codebase.

workspace_path optional
Absolute path to the repository root. Defaults to the workspace the agent is running in.
token_budget optional
Integer. Maximum number of tokens to use (default: 3000). Output is truncated at this limit.
max_depth optional
Integer. Limit directory depth shown in the map (0 = no limit).
include_symbols optional
Boolean. Include symbol signatures alongside file entries (default: true).
directory_filter optional
String. Restrict output to files under this directory prefix, e.g. src/main/java.

find_symbol

Locate class, function, method, annotation, or interface definitions by name. Returns exact file path, line number, symbol kind, and full signature.

query required
Name or partial name of the symbol to find. Supports substring matching across all languages.

find_references

Find all usages, call sites, and import statements for a given symbol across the entire indexed repository.

name required
The symbol name to find references for.

find_callers

Discover all functions and line numbers that call or instantiate a given symbol. Essential before refactoring.

symbol required
The function or class name whose callers you want to find.

find_callees

List all internal functions and symbols invoked inside a given function's body. Useful for understanding a function's dependency chain without reading its full implementation.

symbol required
The function name whose internal calls you want to enumerate.

find_tests_for

Resolve test files and test case names associated with a given source file or symbol. Matches *_test.go, Test*.java, test_*.py, *.spec.ts, and similar conventions.

target required
A file path or symbol name to find tests for.

get_file_skeleton

Read a file's structure — class declarations, method signatures, field definitions — with all function bodies collapsed to line-range markers. Reduces token cost by ~95% compared to reading the full file.

path required
Relative path to the file from the repository root.
Example: A 1,200-line Java controller costs ~6,500 tokens to read in full. get_file_skeleton returns the same file's API surface in ~120 tokens — enough to understand all public methods, their parameters, and return types.

read_file_context

Read a targeted line range from a file with automatic line-drift verification. If the file has changed since the last index, devctx re-syncs the symbol table before returning content — preventing the agent from reading stale line numbers.

path required
Relative file path from the repository root.
start_line optional
Integer. First line to read (1-indexed). Defaults to 1.
end_line optional
Integer. Last line to read (inclusive). Defaults to end of file.

search_code

Full-text search across all indexed file content using SQLite FTS5. Returns matching file paths and highlighted snippets. Much faster than shell grep or IDE global search because it reads from an in-process SQLite index.

query required
Search query. Supports FTS5 operators: AND, OR, NOT, phrase queries with "quotes", and prefix matching with term*.
limit optional
Integer. Maximum number of results (default: 20).

get_git_changes

Returns the current git diff with each changed file mapped to the enclosing AST functions that were modified. Unlike raw git diff, this tells the agent which methods changed, not just which lines.

Returns: branch name, list of changed files with status (modified/added/deleted), affected symbol names, and changed line counts.

pack_feature_context

The highest-value tool. Given a topic keyword, assembles a comprehensive feature context bundle containing: relevant symbol definitions, file skeletons, related test suites, FTS search matches, and stored architectural decisions — in a single response optimized for minimum token use.

topic required
A feature name, module, or concept keyword, e.g. auth, payment, EventController.

blast_radius

Before making a change, calculate the blast radius: all files that reference the target symbol, all direct callers, and all test suites that must be re-run. Returns a risk level (LOW / MEDIUM / HIGH) based on caller count and file spread.

symbol required
The function or class name whose change impact you want to assess.

save_decision / get_decisions

Persistent architectural memory. An AI agent can store design decisions (e.g. "Use DTOs between service and controller layers") during a session. These decisions are preserved in the SQLite index and retrieved in future sessions — so agents don't revisit already-resolved design questions.

topic required
Short topic label, e.g. auth-strategy, api-versioning.
summary required (save only)
The decision text to record.

Index Architecture

The .devctx/index.db SQLite database contains four tables:

TableContentsUsed by
files One row per file: path, language, size, last-modified timestamp, content hash get_repo_map, update
symbols One row per symbol: file path, line number, kind (class/function/annotation/dependency), name, full signature find_symbol, find_callers, blast_radius
files_fts SQLite FTS5 virtual table over all file content for full-text search search_code, pack_feature_context
decisions Architectural decision records: topic, summary, created timestamp save_decision, get_decisions

SQLite WAL Mode

All connections use WAL (Write-Ahead Logging) mode for concurrent read/write safety:

DSN parameters
file:index.db?_pragma=journal_mode(WAL)
             &_pragma=busy_timeout(10000)
             &_pragma=synchronous(NORMAL)
             &_pragma=cache_size(-64000)
             &_pragma=foreign_keys(ON)

This prevents the database is locked (261) error that occurs when multiple MCP clients connect simultaneously. Connection pool is bounded (max 4 open, max 2 idle) to prevent file descriptor exhaustion.

Language Support

LanguageSymbols ExtractedBuild Manifests
Go structs, interfaces, functions, constants, type aliases go.mod dependencies
Java / Spring Boot classes, interfaces, records, methods, fields, annotations (@RestController, @Service, @Bean, @Scheduled, all HTTP mappings) pom.xml, build.gradle
TypeScript / JavaScript classes, interfaces, arrow functions, named exports, React components package.json dependencies
Python classes, functions, decorators, dataclasses requirements.txt, pyproject.toml
Rust structs, enums, traits, impl blocks, functions Cargo.toml
C / C++ functions, structs, classes, enums, typedefs —

All other file types are indexed for full-text search but not AST-parsed. Binary files, build artifacts, and vendor directories are automatically excluded.

Building from Source

devctx uses a standard Go module build. No CGO, no external runtime libraries required (SQLite is compiled in via modernc.org/sqlite).

Prerequisites

  • Go 1.22 or later
  • Git (for version injection via ldflags)

Build commands

bash
# Local binary (current OS/arch)
make build

# Run tests
make test

# Cross-compile all platforms (outputs to dist/)
make build-all

# Manual build with version injection
go build \
  -ldflags "-s -w \
    -X main.Version=v1.0.0 \
    -X main.GitCommit=$(git rev-parse --short HEAD) \
    -X main.BuildDate=$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
  -o devctx .

Release targets

make build-all compiles for: windows/amd64, windows/arm64, darwin/amd64, darwin/arm64, linux/amd64, linux/arm64. Binaries are written to dist/.
