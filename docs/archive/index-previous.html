Raw File Grep vs. codive AST Skeletons

Feeding entire files into LLMs causes "lost-in-the-middle" hallucinations. Skeletons preserve exact signatures and line ranges while leaving out function bodies.

TRADITIONAL RAW FILE READ Whole file

Everything You Need to Know

Straightforward technical answers to questions developers ask before installing.

Never. codive operates 100% locally. The AST index, symbol tables, and caller trees are stored in an embedded SQLite database inside your repository at .codive/index.db. Zero cloud APIs, zero analytics, zero external telemetry.
Graphify is a Python-based knowledge graph tool that outputs static HTML/JSON files. codive is a compiled, single-binary Go context engine designed specifically for real-time AI assistant integration via the Model Context Protocol (MCP). It features local SQLite queries, a localhost graph explorer, signature-only AST skeletons, blast-radius analysis, and persistent memory across agent turns.
Simply run codive setup in your terminal. codive automatically detects installed AI tools (Claude Code, Cursor IDE, Google Antigravity, Windsurf) and writes the necessary MCP configuration and architecture guidelines into their respective config files.
codive natively parses and extracts detailed symbol declarations, function signatures, receiver methods, and call sites for Go, TypeScript, JavaScript, Python, Java, C#, and Rust. Any additional text file (Markdown, JSON, YAML, SQL) is indexed for lightning-fast FTS5 full-text search.
Yes. You can run codive index in your GitHub Actions or GitLab CI workflows to verify that code builds clean and index metadata remains current. Because codive is a single Go binary, it installs in less than 2 seconds with no Python virtual environment dependencies.
